# Архитектура

## Структура

```
src/
  App.tsx          интерфейс, команды, сохранения, модальные окна
  World.tsx        основной R3F-рендер и мост к Rapier
  CanvasWorld.tsx  CPU-рендер при отсутствии WebGL 2
  simulation.ts   независимый Rapier-мир запасного рендера и тестов
  engine.ts       доменные типы, Zod-контракты, локальный планировщик
  store.ts        Zustand, разрешённые действия, снимки состояния
  engine.test.ts  проверки контрактов и реальной физики
server/
  index.ts        Express, LLM proxy, валидация планов, PostgreSQL
```

## Поток команды

Текст → локальный планировщик либо POST /api/plan → JSON-план → planSchema → actionSchema → Zustand → синхронизация физических тел → физический шаг → рендер.

LLM не имеет доступа к DOM, JavaScript eval, файловой системе или SQL. Ответ модели считается недоверенным. Неизвестные типы действий, NaN, бесконечности, некорректные цели и опасные диапазоны отклоняются.

## Разделение состояния

Zustand содержит сериализуемые объекты, окружение, цели и события. `live` — временная карта текущих трансформаций и скоростей от физических тел. Снимок накладывает `live` на сериализуемые данные и проходит snapshotSchema. RigidBody не помещается в JSON.

`revision` повышается при загрузке или телепортации и пересоздаёт физические тела. Сами физические позы не записываются в React на каждом кадре. Время/FPS обновляются раз в секунду. Логи ограничены 100, память 80 событиями. Идентификаторы уникальны в сессии.

## AI

У каждого агента состояния explore / collect / deliver / follow / idle. Дерево приоритетов: доставка переносимой энергии → поиск ближайшего ресурса → ожидание при отсутствии ресурсов. Исследование генерирует меняющуюся цель. Локальная steering-система отталкивает от соседних объектов. Ресурс удаляется только после проверки расстояния и высоты. Сбор и доставка записываются в память.

LLM формирует последовательности разрешённых действий на основании полного снимка и памяти. Без API работает намеренно ограниченный локальный интерпретатор. Персонажи используют utility/decision-поведение, а не заранее записанные диалоги.

## Физика и рендер

Rapier: гравитация, масса, трение, упругость, демпфирование, коллизии, sleeping и broad phase. Фиксированный 1/60 с аккумулятором; скорость времени меняет поступающий в аккумулятор delta. Большие скачки ограничиваются для стабильности.

R3F использует Three.js, тени, hemisphere/ambient/point lights и инстансы статических камней. Canvas использует реальные позиции Rapier, геометрическую изометрическую проекцию, painter ordering, сортировку и интерактивную камеру. Поддержка WebGL определяется до создания основного Canvas.

## Хранение и API

- localStorage: три слота + автослот, endpoint и настройки.
- sessionStorage: API_TOKEN собственного сервера.
- PostgreSQL: `aether_saves(slot PRIMARY KEY, world JSONB, updated_at)`.
- GET /api/health — статус конфигурации без значений ключей.
- POST /api/plan — команда и snapshot; ответ message/actions.
- PUT /api/saves/:slot — проверенный снимок.
- GET /api/saves/:slot — снимок или 404.

CORS allowlist, ограничение тела 2 МБ, обязательный API_TOKEN в production, 20 LLM-запросов в минуту на IP, timeout к провайдеру, параметризованные SQL-запросы. Установка персональная; общее пространство серверных слотов защищено одним токеном.

## Расширение

Новый объект добавляется в objectSchema, makeObject, оба рендера и фабрику коллайдеров. Новое действие — в actionSchema, store.act, server instruction и тестах. Для многопользовательского режима нужен авторитетный сервер симуляции, user/session ownership и транспорт обновлений; текущая игра однопользовательская.
