# Выбор года и SQL-сохранения

- Диапазон: 1800–2100; дискретная геометрия по предшествующему доступному историческому срезу.
- Исторические сущности получают стабильные ID Hxxxxxxxx. Эти ID передаются в модель и валидируются, современные ISO не подставляются вместо исторических стран.
- Исторические NAME и SUBJECTO определяют территории и контролёров из набора Historical Basemaps. Флаги современных стран не приписываются историческим сущностям.
- Дата игры зависит от baseYear и day; mapYear хранится отдельно. Год, по которому движется альтернативная история, не подменяет границы автоматически при каждом тике.
- Создание нового года сохраняет прежний мир, загружает слой, формирует новый мир с отдельным id, сбрасывает часы и старую точку отката.
- Именованные миры, активный мир и SQL-слоты сохраняются отдельно. Слоты являются точками восстановления текущего мира, не отдельными новыми кампаниями.
- SQL-записи содержат полный JSON, название, стартовый год, год слоя, день, ревизию и серверное время. Ревизии защищают от устаревшего автосохранения другой вкладки.
- Hosted: D1 с миграциями. Node: PostgreSQL. Превью без backend использует локальный резерв, явно обозначенный в UI.
- База не требует работающей LLM или квоты провайдера; создание исторического мира также работает без LLM.

## Проверки

Unit/integration: год и диапазон, високосная дата, все исторические наборы и валидация мира, реальная SQL-запись/чтение, версии и 409, ошибочные состояния, отсутствующая база. Browser E2E: смена 1939 → слой 1938, загрузка реальной геометрии, сохранение после очистки браузерного хранилища, открытие разных миров, SQL-слот с годом и геометрией. Playwright направляет тестовые HTTP-запросы в настоящий SQLite-обработчик; production D1 проверяется отдельно после публикации.
