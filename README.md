# AETHER — World Lab

Рабочая браузерная физическая песочница. Авторская подпись: **tilonin**.

## Быстрый запуск

Требуется Node.js 22+.

```bash
npm ci
npm run dev
```

Откройте URL, который напечатает Vite (обычно http://localhost:5173). Игра полностью запускается без сервера: Rapier, агенты, локальные команды и сохранения работают в браузере.

```bash
npm test
npm run build
```

## Управление

- ЛКМ и перетаскивание по пустому месту: вращение камеры.
- ПКМ: панорама; колесо: масштабирование.
- 1–8: инструменты выбора, перемещения, блока, сферы, кристалла, агента, импульса, удаления.
- Инструмент создания: нажмите на остров. Инструмент перемещения: перетаскивайте объект.
- Пробел: пауза. Delete: удалить выделенный объект. `/`: фокус команды. Esc: закрыть окно / снять выделение.
- Инспектор: масса, прочность, смещение X/Y/Z, дублирование, удаление.
- «Агенты»: индивидуальные задачи исследования, сбора, следования или ожидания.
- Камера сбрасывается кнопкой прицела. Панели и консоль скрываются кнопками. Боковые панели прокручиваются. Ширина меняется перетаскиванием внутреннего края панели на компьютере.

## Игровая задача

Доставьте 5 энергокристаллов к центральному маяку. Выберите сценарий «Сбор энергии» или введите «Собери кристаллы». Агенты находят ближайший доступный кристалл, подбирают его, возвращаются к маяку и фиксируют доставку. Прогресс сохраняется вместе с миром. После достижения цели можно продолжать песочницу.

Режимы: Sandbox — свободное создание; Simulation — наблюдение за начальными физическими условиями (новая сессия добавляет 12 блоков); AI Interaction — агенты сразу начинают сбор энергии. При переключении вкладки текущий мир остаётся, при создании новой сессии применяются начальные условия режима.

## Локальные команды

«Создай 5 сфер», «Добавь 2 агентов», «Собери кристаллы», «Исследуй остров», «Следуй за объектом», «Гравитация 4», «Ночь», «День», «Пауза», «Продолжи», «Импульс 8», «Перемести объект в 3 2 -4», «Объясни происходящее».

Составные команды поддерживаются через «и» или `;`. Локальный планировщик ограничен этим набором намерений. Неизвестный запрос сообщает о доступных действиях, не выдумывая результат. Команда перемещения без LLM выбирает первый блок; точное управление выбранным объектом доступно через инспектор. Для свободного языка нужен API-сервер с настоящей моделью.

## Языковая модель и PostgreSQL

Скопируйте `.env.example` в `.env`, задайте `LLM_API_KEY`, модель и при необходимости `DATABASE_URL`. Ключ модели остаётся на сервере.

```bash
npm run server
```

В другом терминале запустите `npm run dev`. В настройках игры задайте `http://localhost:3001` и API-токен, если установлен `API_TOKEN`. LLM должна поддерживать OpenAI-совместимый `/chat/completions` и JSON output. Ключ модели не вводится в браузере. Токен доступа к собственному API хранится в sessionStorage до закрытия вкладки.

Сервер получает фактическое состояние, память и команду. Модель возвращает план JSON. Zod проверяет типы, диапазоны, число действий и существование целевых объектов; лимит 120 объектов проверяется сервером и клиентом. Только валидные разрешённые действия доходят до движка. Модель не исполняет произвольный код.

Без `LLM_API_KEY` сервер возвращает явную ошибку 503; игра не выдаёт локальные шаблоны за ответ модели. Без PostgreSQL серверные слоты недоступны, но локальные продолжают работать.

## Сохранения

Три ручных локальных слота и отдельный автоматический слот каждые 30 секунд. Ручная загрузка автосохранения — окно новой сессии. При новой сессии прежний мир сначала записывается в автоматический слот. JSON export/import переносит мир между браузерами. Сохраняются позиции, вращения, линейные скорости, масса, прочность, цели агентов, переносимый кристалл, прогресс задания, гравитация, освещение, скорость времени и память. Угловая скорость не сохраняется.

Кнопки серверного сохранения используют PostgreSQL-слот 1. API поддерживает слоты 1–3. Для этой персональной установки авторизация общая через API_TOKEN; для многопользовательского продукта потребуется отдельная авторизация и привязка слотов к пользователям.

## Развёртывание

### Статическая игра

`npm run build` создаёт `dist/`. Публикуйте на статическом хостинге с fallback на `index.html`. Эта версия использует локальные сохранения и планировщик. В настройках можно подключить отдельно развёрнутый HTTPS API-сервер; добавьте URL игры в `ALLOWED_ORIGINS`.

### Полный стек Docker

Установите Docker Compose. Скопируйте `.env.example` в `.env`. Задайте длинные уникальные `API_TOKEN` и `POSTGRES_PASSWORD`; при необходимости LLM_API_KEY. Для внешнего адреса настройте ALLOWED_ORIGINS.

```bash
docker compose up --build -d
```

Откройте http://localhost:8080. В настройках укажите этот же адрес как адрес AI-сервера и API_TOKEN из `.env`. Nginx проксирует `/api` к Node.js; PostgreSQL хранится в именованном томе. Для внешнего размещения используйте HTTPS reverse proxy. Не публикуйте порт PostgreSQL.

## Производительность и совместимость

Основной рендер — Three.js + React Three Fiber. Статические камни инстансированы; геометрия процедурная. Rapier использует фиксированный шаг 1/60, broad phase и sleeping. Лимит 120 объектов, ограничение числа новых объектов в команде, адаптивные DPR/тени при высокой нагрузке. Настройки качества доступны в интерфейсе.

Если WebGL 2 недоступен, включается Canvas 2D с изометрической проекцией и **той же настоящей 3D-физикой Rapier**, камерами, агентами и инструментами. Это запасной рендер, а не заранее записанная анимация. На слабых CPU он работает медленнее GPU-версии.

Цель 60 FPS зависит от устройства; универсальная гарантия не заявляется. Тяжёлый LLM-запрос выполняется асинхронно сервером. При 120 объектах отдельный worker для AI не нужен. Поддерживаются мышь и базовые касания; наиболее удобное управление — на компьютере.

## Проверки и границы верификации

`npm test`: 9 интеграционных / unit-проверок валидатора, команд, лимитов, импорта, реальной физики, паузы, восстановления скорости, столкновений, импульсов и автономной доставки. `npm run build`: строгая проверка TypeScript и production-сборка.

Проверен браузерный сценарий создания сфер и сохранения/загрузки мира. В проверочном браузере WebGL отключён, поэтому визуальная проверка выполнена для Canvas/Rapier. Three.js проверен сборкой, но на GPU в этой среде не проверен. Реальный запрос платному LLM-провайдеру и подключение внешней PostgreSQL требуют предоставленных пользователем ключей и сервера и здесь не проверялись. Docker-конфигурация подготовлена, запуск Docker в этой среде не проверялся.

Подробнее: [архитектура](docs/ARCHITECTURE.md), [механики](docs/MECHANICS.md).

## Обновление: симуляция государств

Новый главный экран — карта государств с 31 показателем каждой страны, слоями данных, масштабированием, выбором страны, временем и хроникой событий. Исходные экономические и демографические числа **синтетические**; торговая сеть условная, не основана на реальных договорах и географии. Это сценарная модель, не достоверный экономический прогноз. Геометрия Natural Earth получена из https://github.com/datasets/geo-countries, упрощена для браузера. Отображение контуров не является политическим утверждением.

Для произвольных событий необходим настроенный LLM API: маршрут `/api/geopolitics`. Без ключа свободные события явно недоступны; карта и временная симуляция работают. Интерпретатор не содержит списка политических команд. Ответ модели — ограниченный JSON из воздействий на метрики, торговлю и временных модификаторов. Движок проверяет страны, диапазоны и пересчитывает взаимосвязанные показатели. Модель выбирает величину первичного воздействия; дальнейшая динамика детерминирована. Коэффициенты упрощённые и не калиброваны по реальным данным.

Архитектура: `src/geopolitics/engine.ts` содержит NaturalLanguageInterpreter, WorldStateManager, EventProcessor, CountryAgent, EconomySimulator, PoliticalSimulator, MilitarySimulator, DiplomacySimulator, PopulationSimulator, ConsequenceEngine и HistoryManager. MapStateRenderer реализован SVG-компонентом в GeoApp.tsx. Индивидуальные автономные реакции пока определяются эвристиками состояния, а не отдельными вызовами LLM для каждой страны.

Автосохранение карты отдельно от 3D-песочницы, три локальных слота и импорт/экспорт JSON. Прошлая 3D-лаборатория доступна из навигации. Текущее расширение не реализует изменение геометрии границ, территориальные фронты, перемещающиеся военные подразделения, инфраструктурные объекты, звуки событий или секундную симуляцию локальных боёв. Эти требования остаются отдельным этапом. Серверное PostgreSQL-хранение нового геополитического снимка пока не добавлено; оно существует для 3D-сохранений.

## Строгая тема и производительность карты

Панели сохраняют расположение, но используют радиус 2 px, непрозрачные нейтральные фоны, тонкие границы без размытия и мягких теней. SVG-фокус обозначается контуром геометрии, без прямоугольного outline. Камера обновляет только SVG transform через requestAnimationFrame; React больше не пересоздаёт список стран на каждом кадре, а animation loop останавливается в покое. Экономика и механики не менялись.

Нажатие показателя ВВП включает красно-жёлто-зелёную окраску с логарифмическим масштабом между минимальным и максимальным значением текущего игрового мира. Выбранная страна сохраняет цвет шкалы; видна только светлая граница. «Обычная карта» восстанавливает прежний политический/географический вид. Это синтетическая статистика текущего сценария.

Для приватной публикации доступна сборка `npm run build:hosted`: Cloudflare-compatible Worker обслуживает сжатые ресурсы и `/api/geopolitics`, используя тот же серверный валидатор и планировщик, что Node.js. Ключ задаётся только как секрет `LLM_API_KEY` в окружении хостинга. Встроенное подключение определяется meta-флагом без ключей в HTML. Локальная/Docker-сборка по-прежнему `npm run build`, Node API запускается отдельно. PostgreSQL и схема игрового мира не менялись.

## Год, исторические карты и серверные миры

В верхней панели нажмите «Мир • год». Введите стартовый год **1800–2100**, выберите готовый год или задайте свой, при желании укажите название и нажмите «Создать мир и обновить карту». Это создаёт отдельный сценарий, не переводит уже сыгранную историю в другой год. Текущий мир предварительно сохраняется; новая дата начинается с 1 января.

Доступны исторические срезы 1800, 1900, 1914, 1920, 1938, 1945, 1960, 1994, 2000, 2010 и современная карта (2026). Между срезами используется **предшествующий**: для 1939 года — геометрия 1938, что явно указано в интерфейсе. Для 2026–2100 используется современная география, без утверждения о будущих границах. Карта загружает другие полигоны и список стран/территорий, а не только перекрашивает современные границы. Источник исторических данных: Historical Basemaps, Andre Ourednik and contributors, https://github.com/aourednik/historical-basemaps . Данные упрощены для браузера; GPL-3.0 и атрибуция приложены в `public/history/`. Набор является исследовательским и приблизительным. Экономические показатели синтетические.

В приватной hosted-версии `.openai/hosting.json` подключает SQL D1 через `DB`. Миграция таблицы `world_saves` хранится в `drizzle/`. `GET /api/worlds` возвращает список, `GET /api/worlds/:id` восстанавливает мир, `PUT /api/worlds/:id` записывает проверенное состояние и версию. Автосохранение — каждые 15 секунд при изменениях; доступны ручная запись, отдельные миры и три SQL-слота. Год, слой карты, параметры, история, отношения и цели процессов восстанавливаются из базы даже после очистки localStorage. localStorage используется как резерв и для предпочтения активного мира. Конфликт версий возвращает 409, а не молча перезаписывает более новую копию. Серверные записи принадлежат единственному владельцу приватного сайта; перед расширением аудитории нужно перейти к персональному namespace по идентификатору пользователя.

В локальном Node.js/Docker-режиме те же маршруты работают через настроенный PostgreSQL (`DATABASE_URL`). В чистом Vite без backend серверные сохранения недоступны; кнопка «Проверить API и базу» проверяет явно заданный сервер, локальные резервные слоты продолжают работать. Для исторических данных в локальном архиве включена вся папка `public/history`, повторное скачивание не требуется.

## Подробная карта (дополнение Real World Map)

В меню «Вид карты» появился пункт **«Подробная карта · города и дороги»**. В этом режиме используется MapLibre GL JS (загрузка JS/CSS из CDN) с растровой подложкой OpenStreetMap, поиском населённых пунктов/улиц через Nominatim и отдельными GeoJSON-контурами государств. Можно переключиться обратно к автономной SVG-карте. Поиск и плитки требуют интернет-соединения; при недоступности CDN режим не загрузится, но исходная карта остаётся рабочей. Это **не Google Earth** и не фотограмметрический 3D-режим.

- Для продуктивного развертывания **настройте собственного лицензированного поставщика тайлов** через `VITE_MAP_TILE_URL` (строка URL с `{z}/{x}/{y}`), а также отдельный геокодер вместо публичного Nominatim. Публичный OSM Tile Service предназначен для умеренного использования с соблюдением правил и атрибуции, не для массовых запросов в публичной игре. JS/CSS MapLibre также следует разместить локально или в инфраструктуре проекта при переводе в production.
- Слой «Условные войска симуляции» показывает агрегированные показатели стран условными маркерами около географического центра. Они **не являются фактическими позициями**. Дополнительно AI-события могут создавать виртуальные дислокации через `deployments` (координаты WGS84, тип, численность, обозначение); они включаются в снимок мира, проходят валидацию и сохраняются вместе с ним. Обобщённые маркеры и явно заданные дислокации отличаются по происхождению данных.
- География подложки соответствует современным картографическим данным даже для исторического сценария; историческими остаются границы, подгруженные через систему сценариев. Данные о дорогах, домах, сёлах зависят от покрытия поставщика плиток. Интерактивные профили каждого поселения, реальные железнодорожные потоки, боевые 3D-анимации, геометрия зданий и Google Photorealistic 3D Tiles **пока не реализованы**.
